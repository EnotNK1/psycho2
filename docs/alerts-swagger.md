# Проверка алертов в Swagger

Проверять локально, на `http://127.0.0.1:8000/docs`. Ветка: `alerts`.
После изменения кода перезапустите Uvicorn или дождитесь `--reload`.
Новые миграции для алертов не требуются.

## Доступ и связь

Нужны два отдельных аккаунта: клиент и психолог (роль 2).
Админ не заменяет психолога: у админа ручка алертов возвращает 403.
Если связь уже подтверждена, повторять заявку не нужно.

Если психолога ещё нет, зарегистрируйте отдельный тестовый аккаунт, войдите
через `POST /auth/login` и вызовите `PATCH /psychologist/become`:

```json
{
  "username": "Психолог для проверки",
  "birth_date": "1990-01-01",
  "higher_education_university": "Тест",
  "higher_education_specialization": "Психология",
  "academic_degree": null,
  "courses": null,
  "work_format": "online",
  "association": null,
  "inquiry_ids": []
}
```

Найдите его UUID в `GET /psychologist`, затем под клиентом отправьте
`POST /applications`:

```json
{
  "manager_id": "UUID психолога",
  "text": "Проверка алертов",
  "inquiry": []
}
```

Под психологом вызовите `GET /applications`, найдите заявку именно этого
клиента и один раз вызовите `PATCH /applications/{app_id}/confirm`.
Повторный вызов переключает статус обратно, поэтому его не нужно повторять.
Для смены аккаунта используйте `POST /auth/login`: авторизация хранится в cookie.
Не публикуйте cookie, пароли и токены в скриншотах.

## Сначала пустой список

Под психологом вызовите `GET /psychologist/alerts`. Для нового клиента без
повышенных результатов список пустой: `[]`. При наличии других клиентов
могут возвращаться их ранее сохранённые высокие результаты.

## Создать повышенный результат

Войдите под клиентом. Выполните `POST /tests/result` с одним из тел ниже.
Это искусственные данные для локальной проверки, не ответы реального человека.
В примерах используются встроенные вопросы и варианты ответов. Если тесты
ещё не загружены, сначала загрузите их локально через `POST /tests/auto`
под администратором. На сервере не синхронизируйте справочники ради проверки.
Если вопросы теста редактировались, проверьте допустимые ответы в
`GET /tests/{test_id}/questions/answers`.

### Бек: 63 балла по общей шкале

```json
{
  "test_id": "33d10952-aed7-4a4e-9e5a-dbd01b2f294d",
  "date": "2026-10-25T12:00:00",
  "results": [3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3]
}
```

### DASS-21: все три шкалы в категории «Высокий»

```json
{
  "test_id": "bc9f1204-ea5d-40b0-b367-359bf9b2cc21",
  "date": "2026-10-25T12:00:00",
  "results": [3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3,3]
}
```

### STAI: обе шкалы в категории «Выше нормы»

```json
{
  "test_id": "3a9a3c8d-348e-4f0d-aefd-0feaa960ac25",
  "date": "2026-10-25T12:00:00",
  "results": [4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4]
}
```

## Увидеть алерт

После успешного сохранения войдите под психологом и повторите
`GET /psychologist/alerts`. Пример формы ответа:

```json
[
  {
    "client_id": "UUID клиента",
    "client_name": "Имя клиента",
    "test_id": "UUID теста",
    "test_title": "Название теста из каталога приложения",
    "test_result_id": "UUID сохранённого прохождения",
    "date": "2026-10-25T12:00:00"
  }
]
```

Проверьте имя клиента, название теста и совпадение `test_result_id` с ответом
`POST /tests/result`. Для кнопки «Результаты» используйте существующий
`GET /tests/test_result/{result_id}` под психологом. Несколько высоких шкал
одного прохождения дают одну карточку. Названия тестов берутся из БД, например
«Есть ли у меня депрессия?», а не заменяются техническим названием методики.

## Отрицательные проверки

- Под клиентом или админом `GET /psychologist/alerts` возвращает 403.
- Без авторизации запрос отклоняется с 401.
- Другой психолог не видит этот алерт, если у него нет активной связи с клиентом.
- Для нормального результата нового тестового клиента алерт не появляется.
  У Бека можно заменить все 21 ответа на 0; у DASS-21 тоже на 0;
  у STAI все 40 ответов на 1.
- Повышенные субшкалы Бека сами по себе не дают алерт: проверяется только
  общая шкала, от 30 до 63 включительно.

## Поведение списка

Это получение списка, не WebSocket и не отправка письма. Фронт повторяет GET,
чтобы получить обновления. Каждое высокое прохождение остаётся отдельным
алертом, новые идут первыми. Нормальное повторное прохождение не удаляет
предыдущий алерт. Старые высокие результаты подтверждённых клиентов также
попадают в список. Отзыв связи скрывает результаты этого клиента.

Крестик реализует фронт, используя `test_result_id` как ключ скрытой карточки.
Сервер не сохраняет прочтение или закрытие и не удаляет результаты тестов.
