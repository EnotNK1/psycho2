# Технические метрики 6, 7, 9, 10, 11, 13

Это описание реализованной основы и воспроизводимых проверок. Численная производительность, SLA, RPO/RTO и результат аудита безопасности **не объявляются достигнутыми** без замеров на целевой инфраструктуре.

| № | Метрика | Что подготовлено | Как проверять |
|---|---|---|---|
| 6 | Устойчивость к нагрузкам | Ограниченный пул БД, таймауты, stateless API, нагрузочный клиент | Нагрузочные замеры, доля ошибок, p95, CPU/RAM, соединения БД |
| 7 | Отказоустойчивость и восстановление | Persistent-том, health/readiness, restart-policy, атомарные записи, дамп и восстановление в новую БД | Остановить/запустить сервисы на стенде, пробное восстановление, сравнить данные и время |
| 9 | Масштабируемость архитектуры | Два процесса API, общий PostgreSQL, отсутствие памяти процесса в критичном состоянии | Сравнить 1/2/4 процесса при одинаковых нагрузке и ресурсах; учесть общий лимит БД |
| 10 | Гибкость архитектуры | Отдельные API, сервисы, репозитории, схемы, конфигурация и каталог | Добавить тест через админские ручки; для нового способа расчёта добавить обработчик и тест |
| 11 | Гибкость работы с данными | 12 предметных таблиц, связи, индексы, уникальные пары, отдельная миграция | Проверить запросы через EXPLAIN ANALYZE на PostgreSQL; изменения схемы через Alembic |
| 13 | Защищённость данных | bcrypt, независимые JWT-ключи, шифрование численных результатов, проверки владельца и роли, безопасная раздача изображений, секреты вне Git | Тесты доступа и токенов, HTTPS, проверка секретов, отдельный аудит и тест восстановления ключей |

## Нагрузка

Запускайте на стенде с заполненным каталогом. Пример:

```powershell
python scripts/load.py --requests 500 --concurrency 10 --output load-results-10.json
python scripts/load.py --requests 1000 --concurrency 30 --output load-results-30.json
docker compose stats --no-stream
```

Клиент выполняет только GET и выводит throughput, p50, p95 и статусы HTTP. По умолчанию проверяется `/tests`. Для защищённой ручки задайте в окружении `COMPAS_ACCESS_TOKEN`; токен не записывается в отчёт. Каталог не воспроизводит дорогой расчёт тестов или массовую запись: эти сценарии необходимо отдельно нагрузить на одноразовой БД с тестовыми аккаунтами.

## Резервное копирование и восстановление

```powershell
python scripts/backup.py create
python scripts/backup.py verify backups/ИМЯ.dump
python scripts/backup.py restore-check backups/ИМЯ.dump
```

`verify` проверяет только структуру архива. `restore-check` создаёт БД со случайным именем `compas_restore_*`, восстанавливает дамп одной транзакцией и выводит ревизию и количества строк. Рабочую БД он не очищает. После проверки отдельно сверьте результаты, вход, алерты и расшифровку с тем же DATA_ENCRYPTION_KEY. Отдельная тестовая БД остаётся для осмотра.

Резервные копии БД и аватаров необходимо хранить вне Docker-хоста; шифровальный ключ отдельно. Скрипт копирует только БД; том `compas_avatars` архивируется отдельно. Согласуйте частоту резервирования и срок хранения, затем подключите расписание на сервере. Автоматическое расписание в этом проекте пока не установлено. После каждого изменения схемы повторите проверку восстановления.

## Миграции

`compas_0001` — собственная начальная ревизия для новой БД. История миграций «Одеяло» сюда не переносится. Для обновления:

```powershell
alembic revision --autogenerate -m "describe change"
# Проверить полученный SQL и совместимость на копии БД.
alembic upgrade head
```

Не подключайте старый том PostgreSQL другого major-релиза. Перенос реальных пользователей и истории требует отдельного согласованного экспорта/импорта, а не подключения production-тома к новому проекту.

## Ограничения

Проект наследует формулы и пороги существующего каталога. Их методическая проверка — отдельная задача. Технические тесты подтверждают сохранение поведения, а не клиническую валидность. Система не содержит ИИ. Работа с данными не проверена на серверной БД и не является полной сертификацией безопасности.
