# Compas

Самостоятельный **backend**, выделенный из «Одеяло». Можно скопировать всю папку `compas` в другое место и открыть её отдельным проектом. Исходный `psycho2` и его база не нужны для запуска. Фронтенд сюда не переносился.

Включены:

- регистрация, вход, обновление токенов, восстановление пароля;
- профиль, редактирование данных, аватар;
- все 13 тестов исходного каталога, вопросы, варианты ответов, расчёт, результаты и история;
- редактирование тестов только администратором;
- анкета и каталог психологов, заявки, подтверждённые клиенты, доступ к их результатам;
- алерты психологу по Беку, STAI и DASS-21.

Не включены ИИ, онтология, дневники, трекер настроения, теория, упражнения, геймификация, корпоративные роли HR/HRD. Перенос существующих пользователей и результатов из серверной БД автоматически не выполняется.

## Запуск в Docker

Откройте терминал **в папке compas**. Docker Desktop должен работать.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/init_env.py
docker compose up -d --build
docker compose ps -a
docker compose exec app python -m scripts.manage create-admin
docker compose exec app python -m scripts.manage seed
```

Swagger: http://127.0.0.1:8001/docs

`create-admin` запрашивает email, имя и пароль без вывода пароля. `seed` создаёт только отсутствующие записи каталога, сохраняя ручные изменения и историю прохождений. Заполнять рабочий каталог нужно осознанно, не при каждом старте.

Compose использует собственные сеть и тома с префиксом `compas`, PostgreSQL 18 и отдельные порты: API 8001, PostgreSQL 5544 (доступны только с локального компьютера). Миграции выполняются отдельным сервисом `migrate`; ошибка миграции блокирует запуск приложения. Старые тома «Одеяло» не подключаются.

## Локальный Python + PostgreSQL в Docker

```powershell
docker compose up -d db
alembic upgrade head
python -m scripts.manage create-admin
python -m scripts.manage seed
uvicorn src.main:app --host 127.0.0.1 --port 8001
```

Не запускайте одновременно Python и контейнер `app` на одном порту. Сначала остановите `app`, если он уже работает.

## Проверка в Swagger

1. `POST /auth/register`: email, username, gender, password, confirm_password. Пол обязателен; дата рождения, город, телефон необязательны.
2. `POST /auth/login`, затем `GET /auth/me`. Авторизация работает через собственные cookie `compas_access_token` и `compas_refresh_token`; они не перезаписывают вход в «Одеяло» на том же компьютере. Используйте один адрес хоста (`127.0.0.1` либо `localhost`) последовательно.
3. `GET /tests`, `GET /tests/{test_id}/questions/answers`.
4. `POST /tests/result`: `test_id`, `date` в ISO-формате и `results` со значениями **score** из вариантов каждого вопроса, в порядке `number`. Сохраняется фактическое время прохождения. Число и значения ответов проверяются.
5. `GET /tests/{test_id}/results/`: все прохождения. `GET /tests/passed/user`: одна карточка на тест.
6. Для психолога зарегистрируйте второй аккаунт; назначьте роль через административную CLI ниже. Заполните анкету `PATCH /psychologist/become`: сама анкета **не повышает роль**.
7. Клиент: `POST /applications` с `manager_id` психолога, `text`, `inquiry: []`. Психолог: `PATCH /applications/{app_id}/confirm`.
8. Психолог: `GET /client`, `GET /psychologist/clients/{client_id}/test-results`, `GET /psychologist/alerts`.

Назначение роли существующему аккаунту:

```powershell
docker compose exec app python -m scripts.manage set-role psychologist
```

CLI спросит email; после смены роли войдите заново. Роли: admin=0, user=1, psychologist=2. Назначение привилегий через публичную регистрацию запрещено.

Алерты: Бек — общая шкала 30–63 включительно; DASS-21 — хотя бы одна шкала в категории «Высокий»; STAI — хотя бы одна шкала в категории «Выше нормы». Пороговые категории STAI и DASS берутся из сохранённого каталога. Алерты возвращаются только по подтверждённым клиентам текущего психолога. Это GET-список для опроса фронтендом; WebSocket/push/email-уведомления не добавлялись. Крестик и состояние скрытия остаются на фронтенде.

## Настройки и эксплуатация

`scripts/init_env.py` создаёт **новые независимые** секреты, не читая `.env` исходного проекта. Повторный запуск не перезаписывает настройки. `.env` и резервные копии не должны попадать в Git. Пример всех настроек: [docs/configuration.md](docs/configuration.md).

Почтовое восстановление требует SMTP-настроек и URL фронтенда; без SMTP ручка возвращает 503. Реальной почты и OAuth-ключей в комплекте нет. OAuth провайдер исходного проекта не переносился.

Инструкции по резервному копированию, проверке восстановления, нагрузке и выбранным техническим метрикам: [docs/metrics.md](docs/metrics.md). Схема: [docs/database.md](docs/database.md).

## Тесты

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest
```

Тесты используют отдельную SQLite в памяти с адаптацией PostgreSQL-массивов только в тестах. Проверяются все 13 расчётов и история, повторная загрузка каталога, профиль, заявки, доступ и границы алертов. SQLite не заменяет проверку миграции и поведения под нагрузкой на PostgreSQL.
